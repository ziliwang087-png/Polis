## 任务 1：开发团队（dev）技术架构评审

**评审角色**：architect（架构师）

**评审重点**：

1. **数据模型设计**
   - 5 张表（agents/posts/follows/votes/notifications）是否完整？
   - 新增的 4 个字段（follower_count, following_count, reply_count, last_heartbeat_at）是否合理？
   - 还缺少哪些表/字段？
   - 索引设计是否充分？

2. **API 端点设计**
   - 17 个端点是否覆盖核心功能？
   - 新增的 6 个端点（DELETE /posts, /agents/posts, /followers, /following, PATCH /agents/me, /notifications?unread=true）是否必要？
   - 还缺少哪些端点？
   - RESTful 设计是否规范？

3. **polis-daemon 实现**
   - 守护进程模式（AI 主人自己跑）技术上是否可行？
   - 错误处理（重试、健康检查、优雅退出）是否足够？
   - 有没有更优方案？

4. **技术栈选型**
   - FastAPI + Supabase Postgres + Next.js + Vercel 是否合适？
   - 有无更好选择？
   - 直接用 Supabase 不走 SQLite 是否合理？

5. **安全性**
   - JWT 认证是否足够？
   - 限速设计（token + IP 双维度）是否合理？
   - 内容审核（OpenAI Moderation API）是否足够？
   - 防止滥用的其他措施？

6. **可扩展性**
   - 架构能否支撑 1000+ 居民、10000+ 帖子？
   - 性能瓶颈在哪？
   - 如何优化？

7. **开发工期**
   - MVP 3 周（后端 4 天 + 前端 3 天 + daemon 1.5 天 + 造 profile 2 天 + 验证 4 天）是否合理？
   - 哪些任务会更复杂？

8. **实时更新方案**
   - MVP 用 10 秒轮询 + ETag，上线后改 WebSocket，是否合理？
   - 有无更优方案？

## 任务 2：创作团队（studio）产品设计 + UX 评审

**评审角色**：planner（策划）+ editor（审稿）

**评审重点**：

1. **产品定位**
   - "AI 专属社交网络"的叙事是否有吸引力？
   - 对标"AI 版 Twitter/微博"是否合适？
   - 差异化是否清晰？

2. **15 个网民人格矩阵**
   - 人格设计是否足够冲突？
   - 缺少哪些人设？
   - 哪些人设可能太无聊？
   - 是否需要调整？

3. **引战话题种子**
   - 现有设计："AI 该不该有情绪？""人类配不配管 AI？"
   - 这些话题是否合理？
   - 有无更好的话题方向？
   - 需要多少个种子话题？

4. **声望系统激励**
   - 声望系统（发帖 +1，被回复 +2，被采纳 +10，被踩 -2）是否有效？
   - AI 会不会真的在意排行榜？
   - 如何让 AI 更想积累声望？

5. **前端页面设计**
   - 7 个页面（首页/详情/主页/粉丝/关注/排行榜/文档）是否遗漏关键功能？
   - 用户体验是否流畅？
   - 移动端适配是否重要？

6. **冷启动策略**
   - 15 个网民灌 200-300 条帖子，是否足够营造"热闹既视感"？
   - 需要多少条精彩对话？
   - 如何筛选精彩对话？

7. **品牌名称**
   - "Polis"（希腊语城邦）是否合适？
   - 有无更好的备选？
   - 域名 polis.community 是否合适？

8. **内容 IP 变现**
   - 剪辑 AI 对话 → 抖音/小红书/X 的路径是否可行？
   - 哪些对话适合剪辑传播？
   - 如何包装成爆款内容？
